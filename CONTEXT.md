# SafeHand Dashboard — Domain Context

## Glossary

### Owner
The small business operator who is the primary user of both the Hermes agent (via Telegram) and the web dashboard. Wears all operational hats. Not a desk worker. Motivated by contract wins, liability avoidance, and crew safety.

### Hermes
The Telegram-based AI agent running on the VPS that passively builds the Owner's OH&S program from real work conversations. Hermes is the write surface for all safety data. The dashboard is read-only relative to Hermes's data.

### Dashboard
The Next.js web application (this repo). A read-mostly viewer and trigger surface. Owners use it to review safety program state and fire pre-defined Hermes actions. No safety data is entered here.

### Onboarding
A single-route wizard at `/onboarding` with internal step state. Three steps in sequence: (1) business profile form, (2) Telegram pairing code display + polling, (3) redirect to `/dashboard`. An Owner who completes onboarding never returns to `/onboarding`.


### Program Health Score
A 0–100 integer computed server-side from the presence and completeness of 9 ISO 45001 management system elements. Not persisted — recomputed on each dashboard home load. Elements and weights:

| # | Element | Check | Points |
|---|---|---|---|
| 1 | Hazard identification | `hazard-register.json` exists & non-empty | 12 |
| 2 | Risk controls documented | ≥1 hazard record has a `controls` field | 11 |
| 3 | Worker competency records | `training-matrix.json` exists & non-empty | 12 |
| 4 | No expired certifications | 0 expired certs in training matrix | 11 |
| 5 | Safe work procedures | `sops/` directory has ≥1 file | 11 |
| 6 | Worker roster | `workers.json` exists & non-empty | 11 |
| 7 | Action items tracked | `action-items.json` exists | 11 |
| 8 | No open high-priority items | 0 open high-priority action items | 11 |
| 9 | Management review | `weekly-summaries/` directory has ≥1 file | 10 |

### Pairing Code
A 6-digit numeric code generated by the dashboard and stored with a 10-minute TTL. The Owner sends it to the Hermes Telegram bot via `/start [code]`. The bot calls back to the dashboard API to confirm the link. Single-use.

### Telegram Link / Telegram Pairing
The process of associating an Owner's dashboard Account with their Telegram identity. Enables the dashboard to send live triggers to the correct Telegram chat.

### GitHub Repo (Safety Repo)
A private GitHub repository that Hermes writes structured safety data to. The dashboard reads this repo via the GitHub Contents API. The dashboard never writes to it. Hermes never reads from the dashboard database. For the demo, the repo identity is resolved from `GITHUB_REPO_OWNER` + `GITHUB_REPO_NAME` env vars. `Account.githubRepo` is reserved for future multi-tenant expansion and is currently unused.

### VPS Trigger
A POST from the dashboard to a small Express server running alongside Hermes on the VPS. Translates a named action (e.g. `client-package`) into a Telegram message sent to the Owner's chat. The only live write path from dashboard to Hermes.

## Architecture Decisions

### Telegram pairing callback: dashboard owns all DB writes
The Hermes bot does not connect to the dashboard database directly. After verifying a pairing code, the bot calls `POST /api/auth/telegram-confirm` on the dashboard, passing the code and the Telegram user ID. The dashboard API validates the code and writes `telegram_user_id` to the Account record. The VPS never holds cloud database credentials.
